# Блог: как устроен и как публиковать статьи автоматически

## Как устроено

- Статья = один файл `content/blog/<slug>.md`. Имя файла становится адресом: `content/blog/kak-doehat.md` → `/blog/kak-doehat`.
- При сборке `src/lib/blog.ts` читает все файлы из папки, разбирает frontmatter и превращает Markdown в HTML (библиотека `marked`).
- `vite.config.ts` сам добавляет каждую статью в пререндер и в `sitemap.xml`. Ничего регистрировать не нужно.
- `/blog` — список статей, `/blog/<slug>` — статья, `/blog/rss.xml` — RSS-лента.
- На каждой статье JSON-LD `Article` + `BreadcrumbList`, og:type `article`, canonical.

Публикация = коммит нового `.md` в `main`. Lovable подхватывает коммит и пересобирает сайт.

## Формат файла

```md
---
title: Как доехать из аэропорта Алматы в город ночью
description: 100–160 знаков, прямой ответ на вопрос заголовка. Попадает в meta description и RSS.
date: 2026-09-11
updated: 2026-09-11
author: Команда Luxx Aparts
cover: 03
tags: как добраться, аэропорт, ночной приезд
---

## Первый раздел — вопрос словами гостя?

Первый абзац — прямой ответ с фактом, 40–75 слов.

## Следующий вопрос?

Текст…
```

Поля:

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `title` | да | H1 и `<title>`, до 60 знаков |
| `description` | да | 100–160 знаков |
| `date` | да | дата публикации, `YYYY-MM-DD`; список сортируется по ней |
| `updated` | нет | дата правки, по умолчанию равна `date` |
| `author` | нет | по умолчанию «Команда Luxx Aparts» |
| `cover` | нет | номер фото из `public/photos` (`01`–`30`), см. `docs/photos/index.txt` |
| `tags` | нет | через запятую |

Slug (имя файла): латиница, дефисы, без дат и id. Например `chto-posmotret-v-almaty-za-2-dnya.md`.

## Правила текста (из ТЗ, раздел 8)

- Заголовки разделов `##` в форме вопроса словами гостя.
- Первый абзац под заголовком — прямой ответ с цифрой, сроком или фактом.
- Название «Luxx Aparts» вместо «мы» и «наш хостел» дальше двух предложений подряд.
- Каждая цена и расстояние — с датой или источником.
- Никаких выдуманных цифр: если факт не подтверждён, писать «уточните у администратора».
- Запрещённые слова: «частный пляж», «лучший хостел Алматы», «гарантируем», «5 звёзд», «незабываемый отдых», «уютная атмосфера», «в самом сердце города».
- Факты о хостеле брать из `src/lib/site.ts` (телефон, адрес, заезд, цена), а не по памяти.

## Как автоматизировать

Любой сценарий сводится к трём шагам: сгенерировать Markdown по формату выше, положить файл в `content/blog/`, закоммитить в `main`.

Вариант через GitHub API (подходит для n8n, Make, cron-скрипта, агента):

1. `GET /repos/zapoinov13/luxx-guide-ai/contents/content/blog` — проверить, что slug ещё не занят.
2. `PUT /repos/zapoinov13/luxx-guide-ai/contents/content/blog/<slug>.md` с телом `{ "message": "Статья: <title>", "content": "<base64 файла>", "branch": "main" }`.
3. Через несколько минут статья доступна по `/blog/<slug>` и в `/blog/rss.xml`.

Проверка перед публикацией, которую стоит встроить в автоматику:

- frontmatter содержит `title`, `description`, `date`;
- длина `title` ≤ 60, `description` 100–160;
- каждый `##` заканчивается знаком вопроса;
- нет запрещённых слов из списка выше;
- `cover` существует в `public/photos`.

Локально то же самое проверяется сборкой: `bun run build` падает, если Markdown не разобрался, а `bun run typecheck` и `bun run lint` ловят ошибки в коде.
